# GLM 5.3 Flash native Swift runtime

Implements the 45 trunk blocks of the `glm5-next` checkpoint: KDA recurrent attention, absorbed sparse DSA with four-token index pooling, four-stream hyper-connections and top-eight MoE. The optional final MTP block and image encoder are not executed. Prefill uses batches of up to 32 tokens; BF16 dense projections use Metal SIMD-group matrix multiplication. Expert applications are grouped per expert and gathered into batched projections. Expert banks stay memory-mapped; only individual selected experts become Metal buffer views, released in bounded waves. This bounds explicitly mapped GPU weight buffers, but is not a guarantee of model fit or sustained speed on 32 GB systems.

The decoder orchestration is Swift. Metal kernels and numerical contracts are ported from `GiorgioOppo/ds4` at commit `acf5c16bb6a01f8c4f027a0db265ae270d8907ab`: `metal/glm53_bf16.metal`, `metal/glm53_kda.metal`, DSA pooling in `metal/dsv4_misc.metal`, and GLM53 decode/prefill in `ds4.c`. The upstream MIT license is retained in `metal/glm53/LICENSE`. The generated Swift shader strings are local to this backend and are appended to the existing Metal library only when loading this architecture.

Synthetic tests cover required metadata, KDA decode/prefill and continuation against a scalar recurrence, BF16 matvec/tiled prefill, Q8/Q4 grouped projections with guarded offset views, routing, absorbed sparse attention and partial pooling. These do not establish end-to-end logits parity against the full 90–178 GiB checkpoint, which has not been downloaded for validation.
